# นำระบบขึ้นออนไลน์ (ได้ URL เข้าจากทุกที่)

## สถาปัตยกรรม — ทำไมต้องแยกสองส่วน

```
┌─ Vercel ─────────────┐        ┌─ Supabase (โตเกียว) ─┐        ┌─ เครื่องคุณ ────────┐
│  เว็บ (Next.js)      │◄──────►│  ฐานข้อมูล + คิวงาน  │◄──────►│  worker + ffmpeg    │
│  มี URL สาธารณะ      │        │  + ไฟล์คลิป          │        │  ไม่ต้องมี URL      │
└──────────────────────┘        └──────────────────────┘        └─────────────────────┘
```

**worker อยู่บนเครื่องคุณ ไม่ใช่บนคลาวด์** เพราะ:

- เรนเดอร์คลิปกินเวลาหลายนาที เกิน timeout ของ serverless ทุกเจ้า
- ต้องมี `ffmpeg` ติดตั้งอยู่จริงพร้อมฟอนต์ไทย
- **ไม่ต้องรับ traffic ขาเข้าเลย** — มันแค่ถาม Supabase เป็นระยะว่ามีงานไหม
  เอาไว้หลัง router บ้านจึงใช้ได้จริง ไม่ใช่ทางลัด

ผลคือ สั่งงานจากมือถือที่ไหนก็ได้ → งานเข้าคิว → เครื่องที่บ้านเรนเดอร์ให้ตอนเปิดอยู่
ปิดเครื่อง = งานค้างอยู่ในคิว ไม่หาย เปิดใหม่แล้วทำต่อ

---

## 1. เชื่อม Vercel กับ repo

1. เข้า https://vercel.com/new
2. เลือก repo **`Kosid-B/yt-only`**
3. Framework ตรวจเจอเองว่าเป็น Next.js — **ไม่ต้องแก้อะไร**
4. **อย่าเพิ่งกด Deploy** ใส่ env ในข้อ 2 ก่อน (ไม่งั้น build แรกจะขึ้นหน้า "ยังตั้งค่าไม่ครบ")

## 2. ใส่ Environment Variables

ในหน้า Vercel → **Settings → Environment Variables** ใส่ 3 ตัว (เลือก Production + Preview + Development):

| ตัวแปร | เอามาจาก |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase → Settings → API → Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | ที่เดียวกัน — anon/publishable key |
| `SUPABASE_SERVICE_ROLE_KEY` | ที่เดียวกัน — service_role key (กด Reveal) |

⚠️ **ห้ามใส่คีย์ที่เหลือ** (`ANTHROPIC_API_KEY`, `GOOGLE_TTS_API_KEY`, `PEXELS_API_KEY`)
คีย์พวกนี้ใช้เฉพาะฝั่ง worker ซึ่งรันบนเครื่องคุณ ใส่บน Vercel ก็ไม่มีอะไรเรียก
มีแต่เพิ่มที่ที่มันจะรั่ว

## 3. Deploy แล้วจะได้ URL

หน้าตาประมาณ `https://yt-only-xxxx.vercel.app` — เปลี่ยนเป็นชื่ออื่นได้ที่ Settings → Domains

## 4. บอก Supabase ว่า URL นี้เข้าได้

ไม่ทำข้อนี้ = ล็อกอินไม่ได้ ลิงก์ในอีเมลจะเด้งกลับ localhost

Supabase → **Authentication → URL Configuration**:

- **Site URL**: `https://<โดเมนที่ได้>`
- **Redirect URLs**: เพิ่ม `https://<โดเมนที่ได้>/auth/callback`
  (คง `http://localhost:3000/auth/callback` ไว้ด้วย จะได้ยังพัฒนาบนเครื่องได้)

## 5. worker ยังรันบนเครื่องคุณเหมือนเดิม

```powershell
cd D:\yt-factory
pnpm worker
```

ไม่ต้องรัน `pnpm dev` อีกแล้วถ้าจะใช้ผ่าน URL — แต่ **worker ต้องเปิดค้างไว้** ไม่งั้นงานจะค้างอยู่ในคิว

## ⚠️ ก่อนเปิดสาธารณะ ต้องรู้

**ใครก็เปิดหน้า login ได้** ระบบใช้ล็อกอินด้วยลิงก์ทางอีเมล คนอื่นสมัครเองแล้วสร้างองค์กรของตัวเองได้
เขา**เห็นข้อมูลของคุณไม่ได้** (RLS กันไว้ และทดสอบแล้ว) แต่จะกินโควตาอีเมลของ Supabase

ถ้าใช้คนเดียว ปิดการสมัครใหม่ได้ที่ Supabase → **Authentication → Providers → Email**
→ ปิด **"Enable sign ups"** แล้วเชิญตัวเองเข้าไปทีเดียวจาก Authentication → Users → Invite

**เครดิตยังใช้ร่วมกันทั้งองค์กร** ถ้าเชิญคนอื่นเข้าองค์กรเดียวกัน ทุกคนใช้เครดิตก้อนเดียวกัน

## ทำไมตั้ง region เป็น `hnd1` (โตเกียว)

อยู่ใน `vercel.json` — ทุกหน้าเป็น server-side rendering และเรียกฐานข้อมูลหลายรอบต่อการโหลดหนึ่งครั้ง
**ระยะทางจากเซิร์ฟเวอร์ถึงฐานข้อมูลจึงถูกคูณด้วยจำนวนรอบ** ส่วนระยะจากผู้ใช้ถึงเซิร์ฟเวอร์นับครั้งเดียว

Supabase อยู่ที่โตเกียว (`ap-northeast-1`) จึงวางเว็บไว้โตเกียวด้วย แม้สิงคโปร์จะใกล้ผู้ใช้ไทยกว่า

ถ้าวันหนึ่งย้าย Supabase ไปสิงคโปร์ ให้เปลี่ยนตรงนี้เป็น `sin1` ด้วย

## ตรวจว่าใช้ได้จริง

- [ ] เปิด URL แล้วเห็นหน้า login (ไม่ใช่ "ยังตั้งค่าไม่ครบ" — ถ้าเห็นแปลว่า env ไม่ครบ)
- [ ] ล็อกอินด้วยอีเมลแล้วลิงก์พากลับมาที่โดเมนใหม่ ไม่ใช่ localhost
- [ ] เห็นองค์กรกับคลิปเดิมครบ (ฐานข้อมูลเดียวกับตอนรันบนเครื่อง)
- [ ] เปิด `pnpm worker` บนเครื่อง แล้วสั่งสร้างสคริปต์จากมือถือ → งานเดินจริง

## ถ้าเจอ `MIDDLEWARE_INVOCATION_FAILED`

middleware ทำงานกับทุก request ล้มเมื่อไรเว็บ 500 ทั้งใบรวมถึงหน้า login
โค้ดตอนนี้ห่อ try/catch ไว้แล้ว เจอ error นี้ = ยังไม่ได้ deploy เวอร์ชันที่แก้

**สาเหตุที่พบบ่อยที่สุด เรียงตามโอกาส**

| สาเหตุ | ตรวจยังไง |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` มีช่องว่าง/ขึ้นบรรทัดใหม่ติดมาตอน copy | เปิดค่าใน Vercel ดูว่ามี space ท้ายไหม |
| ใส่ URL ไม่ครบ (ลืม `https://`) | ต้องเป็น `https://xxxx.supabase.co` เต็ม ๆ |
| ใส่ env แล้วแต่ยังไม่ redeploy | Vercel ไม่เอา env ใหม่ไปใช้กับ deployment เดิม ต้อง **Redeploy** |
| เลือก environment ไม่ครบ | ต้องติ๊ก Production ด้วย ไม่ใช่แค่ Preview |

**ดู error จริง**: Vercel → โปรเจค → **Logs** → กรอง `Edge Middleware`
ข้อความจะขึ้นต้นด้วย `[middleware]`

**หมายเหตุ** — `regions: ["hnd1"]` ใน `vercel.json` ใช้กับ serverless function เท่านั้น
**middleware รันที่ edge ทุกภูมิภาคเสมอ** เห็น `sin1` ใน error ไม่ได้แปลว่าตั้งค่าผิด
