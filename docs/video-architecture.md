## ทำไมต้องแยกชั้นขนาดนี้

OpenAI ประกาศเลิก Videos API + `sora-2` + `sora-2-pro` วันที่ **24 ก.ย. 2569**
โดยแจ้งล่วงหน้าแค่ 6 เดือน ผู้ให้บริการวิดีโอเปลี่ยนเร็วกว่าโมเดลภาษามาก

ถ้าตรรกะธุรกิจเรียก SDK ของเจ้าใดเจ้าหนึ่งตรง ๆ วันที่เขาปิดเราต้องรื้อทั้งเส้นทาง
ไม่ใช่แค่เปลี่ยน adapter

### งานสร้างวิดีโอเป็น "งานยาว" ไม่ใช่ request-response

ต่างจาก provider layer อื่นในโปรเจคนี้ (`llm.ts`, `tts`, `image-gen`) ที่เรียกแล้วได้ผลเลย

```
generate()  →  providerJobId        (ทันที)
getStatus() →  running / done / failed   (ถามเป็นระยะ นาที ไม่ใช่วินาที)
getResult() →  bytes
```

เขียนเป็นฟังก์ชันเดียวที่รอจนเสร็จจะ**ค้าง worker ทั้งตัว** และ retry ทีไรก็
เสียเงินสร้างใหม่ทุกครั้งเพราะไม่มี id ให้กลับไปถาม

## นโยบายการเลือกเจ้า (Routing)

| นโยบาย | เริ่มจากระดับ | ใช้เมื่อไร |
|---|---|---|
| `cheap` | lite | ทำหลายชิ้นเพื่อคัด |
| `fast` | fast | คุณภาพกลาง ราคากลาง |
| `quality` | quality | ชิ้นที่จะเอาไปยิงแอดจริง |
| `auto` | quality แล้วลดลง | เอาดีที่สุดเท่าที่งบต่อชิ้นไหว |

**ตัดสินจาก 4 อย่าง ตามลำดับ**
1. เจ้าไหนตั้งคีย์ไว้บ้าง (ไม่มีคีย์ = ไม่มีอยู่)
2. ระดับที่นโยบายขอ
3. งบต่อชิ้น (`MAX_VIDEO_COST_USD`)
4. ราคาถูกสุดในบรรดาเจ้าที่เข้างบ

**ลดระดับทีละขั้น ไม่ร่วงไปถูกสุด** — งบ $1 กับคลิป 8 วินาที ยังจ่าย fast ($0.80) ไหว
การไปเอา lite ($0.40) ทั้งที่งบพอ คือลดคุณภาพเกินจำเป็น

**ลดแล้วต้องบอกเสมอ** — `Route.downgraded` ติดธงไว้ให้ UI แสดง
เปลี่ยนคุณภาพเงียบ ๆ คือหลอกผู้ใช้

**ต้อง deterministic** — อินพุตเดียวกันต้องได้เจ้าเดียวกันเสมอ ไม่งั้นผู้ใช้เห็นราคา
ตอนกดแล้วโดนอีกราคาตอนจ่าย (ไม่มีการสุ่ม ไม่อ่านเวลา ไม่ยิงเน็ตใน `router.ts`)

## ด่านคุมงบ

```
MAX_VIDEO_COST_USD          เพดานต่อคลิปหนึ่งชิ้น (ค่าเริ่มต้น 5)
MAX_VIDEO_DURATION_SECONDS  ความยาวสูงสุดที่ขอได้ (ค่าเริ่มต้น 30)
```

**ทำไมต้องมีทั้งที่มีระบบเครดิตอยู่แล้ว** — เครดิตกันได้แค่ "จำนวนงาน" ไม่ได้กัน
"ขนาดของงานแต่ละชิ้น" บั๊กที่ส่งความยาวผิดหน่วยไปหนึ่งครั้ง (8 → 800) ทำเงินหาย
สิบเท่าในคำสั่งเดียวโดยเครดิตไม่รู้สึกอะไร

**ห้ามเชื่อราคาจากเบราว์เซอร์เด็ดขาด** — `schema.ts` ไม่มีช่องราคา ช่องชื่อเจ้า
หรือช่องชื่อรุ่นให้ผู้ใช้กรอก ผู้ใช้ส่งได้แค่ "อยากได้อะไร" ราคาคิดจากฝั่งเราเท่านั้น

**แยก `estimated_cost_usd` กับ `actual_cost_usd`** — ค่าประมาณคือตัวเลขเดียวที่มี
ตอนตัดสินใจ ส่วนบิลจริงมาทีหลังและไม่เท่ากัน เอาค่าประมาณไปคิดกำไรขาดทุน
= ตัวเลขธุรกิจผิดทั้งชุด

**Runway: ไม่รู้ราคา = ไม่ให้ใช้** — Runway คิดเป็นเครดิตซึ่งราคาต่อเครดิตต่างกัน
ตามแพ็ก `estimateCostUsd()` จึงโยน error เมื่อไม่ได้ตั้ง `RUNWAY_USD_PER_SECOND`
ตั้งใจให้เป็นแบบนั้น เดาราคาแล้วปล่อยผ่าน = งบบานโดยไม่มีใครรู้

## ความปลอดภัย

### RLS

ทุกตารางเปิด RLS และใช้กติกาเดียวกัน: **เห็นเฉพาะองค์กรที่ตัวเองเป็นสมาชิก**

```sql
using (is_org_member(org_id))                                    -- อ่าน
using/with check (has_org_role(org_id, ['owner','admin','editor'])) -- เขียน
```

⚠️ **ใช้ `org_id` ไม่ใช่ `workspace_id`** — repo นี้ใช้ `organizations` / `org_members` /
`is_org_member()` ทั้งระบบ ใช้ `workspace_id` = ทุก policy อ้างฟังก์ชันที่ไม่มีอยู่

⚠️ **`WITH CHECK` ไม่ใช่ของประดับ** — policy ที่มีแต่ `USING` ยอมให้แก้ `org_id`
ของแถวตัวเองให้ไปโผล่ในองค์กรอื่นได้ ต้องมีทั้งคู่

⚠️ **ไม่เชื่อ `org_id` ที่เบราว์เซอร์ส่งมา** — server action หา org จากสมาชิกภาพของ
session เสมอ (`actor()` ใน `actions.ts`) เพราะการเขียนต้องใช้ service client
ซึ่งข้าม RLS ถ้ารับ org_id จากเบราว์เซอร์แล้วเอาไปเขียน ชั้นกันนั้นหายไปทั้งชั้น

### ตรวจ RLS จริง

```bash
psql "$DATABASE_URL" -f supabase/tests/video_rls_verification.sql
```

สร้างผู้ใช้จริงสองคนคนละองค์กร แล้วลองแตะข้ามกันจริง — การดูว่า "มี policy อยู่"
ไม่ได้พิสูจน์ว่า "มันกัน"

ผลที่ได้เมื่อ 22 ส.ค. 2569 — ผ่านทั้ง 6 ข้อ:

| ข้อ | ผล |
|---|---|
| SELECT ข้ามองค์กร | 0 แถว |
| UPDATE ข้ามองค์กร | 0 แถว |
| DELETE ข้ามองค์กร | 0 แถว |
| INSERT ยัดเข้าองค์กรอื่น | ถูกบล็อก |
| SELECT `video_generations` ข้ามองค์กร | 0 แถว |
| เจ้าของเห็นของตัวเอง | 1 แถว |

## บันทึกเหตุการณ์ (Observability)

`log.ts` ออกเป็น JSON บรรทัดเดียว เพื่อให้ค้นและรวมยอดได้

| เหตุการณ์ | เมื่อไร |
|---|---|
| `generation_requested` | รับคำขอ |
| `provider_selected` | router เลือกเสร็จ (มี `downgraded`) |
| `provider_job_started` | ผู้ให้บริการรับงานแล้ว |
| `generation_completed` | เสร็จ |
| `generation_failed` | ล้ม (มี `errorCode`) |
| `generation_retry` | ลองใหม่ |
| `generation_cancelled` | ยกเลิก |

ทุกเหตุการณ์มี `latencyMs`, `estimatedCostUsd` เมื่อมี

⚠️ **ห้ามใส่**: คีย์ API, โทเคน, อีเมล/ชื่อผู้ใช้, prompt เต็ม
prompt อาจมีข้อมูลธุรกิจของลูกค้า — เก็บแค่ `promptChars`

## เพิ่มผู้ให้บริการใหม่

1. `src/lib/video/providers/<ชื่อ>/adapter.ts` — `export function create<ชื่อ>Provider(): VideoProvider`
2. `src/lib/video/providers/<ชื่อ>/types.ts` — รูปร่างคำตอบเท่าที่ adapter ใช้

## ที่ยังไม่ได้ทำ

- **AI Marketing Director** — ตอนนี้ผู้ใช้เขียน prompt เอง ยังไม่มีตัวแปลง
  เป้าหมายธุรกิจ → ICP → hook → script → storyboard อัตโนมัติ
  (`video_scripts` เตรียมตารางไว้แล้ว)
- **ยังไม่ได้ยิงกับ API จริงทั้งสองเจ้า** — ไม่มีคีย์ในเครื่องพัฒนา
  รูปแบบคำขอ/คำตอบอ้างจากเอกสาร เทสต์ทั้งหมดใช้ mock
  เรียกครั้งแรกให้ดู log ว่าตรงไหม โดยเฉพาะชื่อฟิลด์ของ operation
- **ยังไม่ได้ต่อเข้าคิวงาน** — ตอนนี้ server action สั่งแล้วบันทึก `provider_job_id`
  แต่ยังไม่มีใครวน `getStatus()` จนจบ ขั้นต่อไปคือ job kind `video_poll`
  ที่ใช้ `DeferJobSignal` (ตัวที่ใช้ตอนโควตา YouTube เต็ม) วนถามโดยไม่ค้าง worker
- **ยังไม่ได้โหลดไฟล์เก็บขึ้น Storage** — `getResult()` มีแล้วแต่ยังไม่มีใครเรียก
  ต้องทำพร้อมกับ job ข้างบน (ลิงก์ของผู้ให้บริการหมดอายุ ต้องรีบโหลด)
- **ปุ่มดาวน์โหลด** ชี้ไป `/api/video/<id>/download` ซึ่งยังไม่มี
- **Rate limiter อยู่ในหน่วยความจำ** — ใช้ได้จริงเมื่อรัน instance เดียว
  บน Vercel หลาย instance ตัวนับแยกกัน เพดานจริง = เพดานที่ตั้ง × จำนวน instance
  เปลี่ยนเป็น Redis เมื่อขึ้น production จริง (ชั้นนามธรรมพร้อมแล้ว)
- **`video_generation_metrics` ยังไม่มีใครเขียน** — รอเชื่อมกับแพลตฟอร์มปลายทาง
