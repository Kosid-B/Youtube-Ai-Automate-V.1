# ประกอบคลิปไทยด้วย ffmpeg

ความรู้ทั้งหมดในไฟล์นี้มาจากการรัน ffmpeg จริงในโปรเจคนี้ ไม่ใช่จากเอกสารหรือการเดา
ทุกข้อที่เขียนว่า "ทดสอบแล้ว" คือรันจริงและเห็นผลด้วยตาหรือด้วยตัวเลข

## กฎข้อเดียวที่สำคัญที่สุด

**ห้ามสรุปว่าคำสั่ง ffmpeg ใช้ได้ ถ้ายังไม่ได้รันมันจริง**

ตัวกรองของ ffmpeg ล้มเหลวแบบ "ผ่านแต่ไม่ทำงาน" ได้บ่อยมาก และ exit code 0
ไม่ได้แปลว่าผลลัพธ์ถูก บั๊กสามตัวที่เสียเวลาที่สุดในโปรเจคนี้ล้วนผ่านเทสต์ที่ตรวจแค่สตริง
แล้วไปพังตอนรันจริง — ดูหัวข้อ "โหมดพังที่เงียบ" ข้างล่าง

## โครงสร้าง

```
scenes + ความยาวเสียงจริง + พาธภาพ/เสียง
        ↓ buildRenderPlan()          src/lib/render-plan.ts   (ไม่รู้จัก ffmpeg เลย)
   RenderPlan (ไทม์ไลน์ + cue ซับ)
        ↓ buildFfmpegCommand()        src/lib/ffmpeg.ts        (pure — คืน args ไม่รัน)
   { args, filterGraph }
        ↓ execFile                    worker/handlers/video-render.ts
```

แยกสามชั้นเพราะจะเปลี่ยนโปรแกรมปลายทาง (เช่น CapCut draft) ก็เขียนตัวแปลงจาก
`RenderPlan` ตัวเดียว ไม่ต้องแตะตรรกะการวางเวลา · `buildFfmpegCommand` เป็น pure function
คืน args อย่างเดียว จึงเทสต์ได้โดยไม่ต้องมี ffmpeg และเทสต์ได้อีกชั้นด้วยการเอา args ไปรันจริง

## กับดักที่เจอมาแล้ว — อย่าให้เสียเวลาซ้ำ

### 1. escape ค่าออปชันของ filter ต้องสองชั้น ไม่ใช่ชั้นเดียว ⚠️ พังหนักสุด

ffmpeg แกะสตริงสองรอบ: รอบแรกระดับ filtergraph รอบสองระดับออปชันของ filter
`\` ชั้นเดียวถูกกินหมดตั้งแต่รอบแรก รอบสองจึงเห็นอักขระดิบ

```
พาธจริง      C:\Users\Kosid\sub.srt
escape ผิด   C\:\\Users\\Kosid\\sub.srt      ← ชั้นเดียว
escape ถูก   C\\:\\\\Users\\\\Kosid\\\\sub.srt  ← สองชั้น
```

อาการเมื่อผิด: ffmpeg อ่านชื่อไฟล์เป็นแค่ `"C"` แล้วโยนที่เหลือไปเป็นออปชันตัวถัดไป
(`original_size`) ล้มด้วยข้อความที่ดูไม่เกี่ยวอะไรเลย:

```
Unable to parse "original_size" option value "UsersKosid...sub.srt" as image size
```

**บั๊กนี้เงียบสนิทบน Linux** เพราะพาธ POSIX ไม่มีทั้ง `:` และ `\` — พาธ Windows ชนทุกเส้น
เพราะขึ้นต้นด้วย `C:\` เสมอ อยู่ที่ `escapeFilterValue()` ใน `src/lib/ffmpeg.ts`

### 2. `zoompan` นับเป็นเฟรม ไม่ใช่วินาที

`d=` คือจำนวนเฟรม ต้องคูณ fps ก่อนเสมอ ใส่วินาทีตรง ๆ จะได้ฉากยาว 1/24 ของที่ต้องการ

### 3. ต้องขยายภาพ ×4 ก่อนเข้า `zoompan`

zoompan ปัดตำแหน่งเป็นพิกเซลเต็มของภาพต้นทาง ไม่ขยายก่อนภาพจะเลื่อนกระตุกเป็นขั้น ๆ
(`UPSCALE = 4` ใน `src/lib/ffmpeg.ts`) — อาการนี้เห็นด้วยตาเท่านั้น ตัวเลขไม่ฟ้อง

### 4. `offset` ของ `xfade` นับสะสมจากต้นสายที่ต่อมาแล้ว

ไม่ใช่นับจากต้นฉากถัดไป คิดผิดข้อนี้ฉากหลัง ๆ จะเลื่อนสะสมไปเรื่อย ๆ จนเสียงกับภาพหลุดกัน

### 5. ภาพนิ่งต้องมี `-loop 1` และ `-t`

ไม่งั้น ffmpeg อ่านเฟรมเดียวแล้วจบ ได้คลิปยาวเสี้ยววินาที

### 6. ใส่ `subtitles` หลัง `xfade` เสมอ

ใส่ก่อน = ตัวหนังสือถูกซูมและเฟดไปกับภาพด้วย

### 7. ตัดความยาวด้วย `-t` ที่ผลรวมเสียง

ภาพฉากท้ายมีหางเฟดเผื่อไว้ ถ้าไม่ตัดคลิปจะยาวเกินและจบด้วยภาพนิ่งเงียบ ๆ

## ฟอนต์ซับไทย

| ระบบ | ฟอนต์ที่มีอักษรไทยครบ |
|---|---|
| Linux | Loma (ค่าเริ่มต้นในโค้ด), Sarabun |
| Windows | Leelawadee UI, Tahoma |
| macOS | Thonburi |

ตั้งผ่าน env `SUBTITLE_FONT` (และ `SUBTITLE_FONTS_DIR` ถ้าใช้ไฟล์ฟอนต์ที่ไม่ได้ติดตั้งในระบบ)
อ่านใน `subtitleStyle()` ที่ `worker/handlers/video-render.ts`

**⚠️ ตั้งชื่อฟอนต์ผิดไม่มีอะไรฟ้องเลย** — ทดสอบแล้ว: ใส่ `FontName=NoSuchFontXYZ`
ffmpeg **exit 0** และเฟรมที่ได้เหมือนตอนใช้ Loma **ทุกพิกเซล** (วัดด้วย
`blend=all_mode=difference` + `blackframe` ได้ `pblack:100`) เพราะ libass ทำ
fallback **ระดับตัวอักษร** ไปหยิบฟอนต์อื่นในเครื่องที่มีอักษรไทยมาวาดแทน

ความเสี่ยงจริงจึงคือ **"ซับเปลี่ยนหน้าตาเงียบ ๆ"** ไม่ใช่ "กลายเป็นสี่เหลี่ยม"
และตรวจจับอัตโนมัติไม่ได้ ต้องตั้งให้ตรงเครื่องเอง

### ffmpeg ที่ใช้ได้ต้องมี 3 อย่างนี้

```
--enable-libass       วาดซับ (ไม่มี = ซับไม่ติดเลย)
--enable-libharfbuzz  จัดวางสระบน/ล่าง
--enable-libfribidi   ลำดับการวาดอักขระ
```

สองตัวหลังคือหัวใจของภาษาไทย ไม่มีแล้วสระกับวรรณยุกต์จะหลุดจากพยัญชนะ ตรวจด้วย
`ffmpeg -version` แล้วดูบรรทัด `configuration:`

ยืนยันใช้งานได้จริงแล้ว: **ffmpeg 6.1 (Linux)** และ **ffmpeg 9.0 full build (Windows)**

## โหมดพังที่เงียบ — และวิธีจับ

`subtitles` filter "ผ่าน" แต่ไม่วาดอะไรเลยได้ (พาธผิด ฟอนต์ไม่มีอักษรไทย หรือเวลา cue
ไม่ตรงกับช่วงไหนเลย) ไฟล์ออกมาปกติทุกอย่าง ความยาวถูก ขนาดถูก มีเสียง — แค่ไม่มีตัวหนังสือ
**ffprobe จับไม่ได้** เพราะซับถูกเบิร์นลงภาพไปแล้ว ไม่ใช่ stream แยก

วิธีจับ: ดึงแถบล่างของเฟรมกลางคลิปมาเป็นค่าความสว่างดิบ พื้นหลังเข้ม ตัวหนังสือขาว
ถ้าไม่มีอะไรวาดค่าสูงสุดจะต่ำ

```bash
ffmpeg -v quiet -ss 1.5 -i out.mp4 -frames:v 1 \
  -vf 'crop=640:100:0:260' -f rawvideo -pix_fmt gray - | \
  od -An -tu1 -v | tr ' ' '\n' | grep -v '^$' | sort -n | tail -1
# มีซับ ≈ 255 · ไม่มีซับ ≈ 22
```

เทียบสองไฟล์ว่าต่างกันจริงไหม (ใช้ตอนสงสัยว่าการตั้งค่ามีผลจริงหรือเปล่า):

```bash
ffmpeg -i a.png -i b.png -filter_complex \
  'blend=all_mode=difference,blackframe=amount=0:threshold=1' -f null - 2>&1 | grep blackframe
# pblack:100 = เหมือนกันทุกพิกเซล (= การตั้งค่าไม่มีผล)
```

⚠️ อ่านค่านี้แบบ "100 เท่านั้นคือเหมือนกัน" — ทดสอบแล้วว่าเฟรมที่มีซับกับไม่มีซับ
ได้ `pblack:99` เพราะตัวหนังสือกินพื้นที่แค่ไม่กี่เปอร์เซ็นต์ของเฟรม
ต่ำกว่า 100 แม้แค่ 1 ก็แปลว่าต่างกันจริง อย่าไปคาดหวังตัวเลขที่ลดฮวบ

## กติกาเวลาแก้โค้ดส่วนนี้

1. **เทสต์ที่ตรวจแค่สตริงไม่พอ** — บั๊ก escape สองชั้นผ่านเทสต์สตริงมาได้เพราะเทสต์
   เขียนตามสิ่งที่ผู้เขียนเข้าใจ ซึ่งผิดตั้งแต่แรก ต้องมีเทสต์ที่เอา args ไปรัน ffmpeg จริงคู่กันเสมอ
2. **พิสูจน์ว่าเทสต์ใหม่จับบั๊กได้จริง** — ย้อนโค้ดกลับเป็นของเดิมแล้วดูว่าเทสต์แดง
   ถ้าไม่แดง = เทสต์ผ่านเปล่า ๆ ไม่ได้ป้องกันอะไร
3. **บั๊กที่ขึ้นกับระบบปฏิบัติการต้องจำลองให้ได้ในฝั่งที่ CI รัน** — เช่นสร้างโฟลเดอร์ชื่อ
   `C:\Users\ทดสอบ` บน Linux (POSIX อนุญาต `:` และ `\` ในชื่อไฟล์ ส่วน Windows ไม่อนุญาต
   และไม่ต้องจำลอง เพราะได้ `C:\` ติดมากับ temp path อยู่แล้ว)
4. **เทสต์ที่ข้ามตัวเองต้องตะโกนบอก** — ชุดเรนเดอร์จริงข้ามอัตโนมัติเมื่อไม่มี ffmpeg
   ถ้าเงียบ ผลรวมจะขึ้นเขียวทั้งที่ ffmpeg ไม่เคยถูกเรียก แล้วคนอ่านจะสรุปผิดว่าเครื่องพร้อม
5. **ทุกกับดักที่เจอใหม่ ให้เขียนกลับมาที่ไฟล์นี้** พร้อมวิธีที่ใช้พิสูจน์

## ตรวจอย่างเร็ว

```bash
cd yt-factory
pnpm test            # ต้อง 78 ผ่าน "ไม่มี skip" — มี skip = เรียก ffmpeg ไม่ได้
ffmpeg -version      # ดู 6.0+ และ libass/libharfbuzz/libfribidi ใน configuration
```
